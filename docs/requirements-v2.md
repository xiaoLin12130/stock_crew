## 一、需求清单（今日新增，全部已由用户提出）

### R1 盘中实时数据（不做「等收盘才有当日数据」）
- 指数：盘中实时点位/涨跌幅/开高低/昨收（东财 push2 ulist → 腾讯 qt.gtimg.cn 备用）；
- 涨跌停/炸板/封板率/梯队：同花顺 dataapi 盘中统计；
- 板块：涨幅/主力资金流（东财 clist → **腾讯行业排行** → 浏览器同花顺）；
- 快讯：新浪 7x24；
- 个股：任意个股实时行情（东财 stock/get），支持**名称或代码**查询（东财 suggest → 腾讯 smartbox）；
- 交易时段判定（盘前/竞价/上午/午间/下午/已收盘/非交易日）；
- 接口：`GET /api/data/realtime`（4 块**并行**，≤20s）、`GET /api/data/quote`、`GET /api/data/search`；
- 前端：首页「实时数据」卡片（指数 KPI、涨跌停、板块榜、快讯、个股查询、30s 自动刷新、
  来源与降级标注、红涨绿跌）。

### R2 浏览器解析 HTML 方案（API 无解时的兜底）
- Playwright + 系统 Edge 无头：页面 JS 自动执行（同花顺 v Cookie），页面内 fetch 取数；
- 已接入：同花顺板块页（q.10jqka.com.cn/thshy，`tools/browser_crawler.py`）；
- 边界：仅作备用源；playwright 仅装 .venv；失败必须降级标注，绝不阻塞主流程。

### R3 时间模式按当前时间自动选择
- 首页复盘表单：日期为今天时自动选择最合适模式（6 窗口映射），可手动覆盖/重新选择；
- 历史日期仍手动选择。

### R4 复盘引擎取数链数据兜底（**本次核心缺口**）
- 现状问题：早盘复盘时 指数/分时/板块/情绪/资讯 大面积「无数据」——
  复盘链主源（通达信 akshare 慢、东财 502、通达信本地 minline 缺失、同花顺 akshare
  依赖被禁用的 mini_racer）故障后没有接入已验证的备用源；
- 目标：复盘链与实时面板**共用同一套备用源**，任一主源故障自动降级且标注来源：
  | 复盘数据块 | 主源 | 新增备用链 |
  |---|---|---|
  | 指数日线/均线 | 通达信 akshare | **东财 push2his HTTP 日K** → **腾讯日K** → 通达信本地 → 缓存 |
  | 分时/分钟线 | 东财 | **腾讯分时** → 通达信本地 → 缓存 |
  | 板块 | 同花顺 akshare | **腾讯行业排行** → 同花顺(浏览器) → 东财 → 缓存 |
  | 资讯 | 财新/央视 | **新浪7x24** → 缓存 |
  | 情绪（昨日涨停今日表现） | Tushare（收盘后可算） | 同花顺统计（盘中只有统计口径，明确标注）→ 通达信本地 |
- 降级链统一：主源 → 备用 → 缓存 → 标注「数据缺失/估算」，绝不静默。

### R5 运维（已完成交付，纳入文档）
- 一键启动：启动服务.bat / 启动隧道.bat；隧道重启后地址变化须重新抓取打印；
- 网络错误前端统一中文化；实时接口 ≤20s 预算、前端 45s 超时。

## 三、口径与铁律（沿用）
- 比率小数、None→「—」、红涨绿跌、免责声明强制、降级可见；
- 每源 ≤15s、块级 ≤20s、前端 fetch 45s；
- 龙虎榜/竞价/财新历史等**天然不可实时**的项：标注「收盘后数据」或「仅窗口期」，不硬凑。

## 四、验收流程（本次 R4）
1. 单测：新增备用源函数（东财 push2his/腾讯日K/腾讯分时/腾讯行业/新浪7x24）离线 mock 用例；
2. 全量 pytest 全绿 + npm build + normalize；
3. 真实冒烟：今日 intraday_am 复盘，检查报告/快照中 指数/分时/板块/资讯 非空且来源标注正确；
4. 提交推送 + PROGRESS 存档。
